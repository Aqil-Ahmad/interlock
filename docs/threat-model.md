# Threat model

Reviewed as the sandbox and MCP server evolve.

## What Interlock is trusted with

| Asset                              | Why it matters                                            |
| ---------------------------------- | --------------------------------------------------------- |
| Uncommitted work in user worktrees | exists nowhere else; loss is unrecoverable                |
| Repository source code             | may be proprietary; must never leave the machine          |
| Developer machine and credentials  | the daemon runs with the user's privileges                |
| Agent attention                    | a warning channel that can be poisoned can steer an agent |

## Trust boundaries

1. **User repositories → Interlock.** Read-only.
2. **Merged code → execution.** Code produced by merging two agent branches has been reviewed by nobody. Untrusted input, executed only in the sandbox.
3. **Interlock → agents.** Everything forwarded is content other agents wrote. Untrusted data, wrapped as data.
4. **Localhost API.** Any process on the machine can reach a loopback port; the bearer token is the boundary. Agent hooks post through it, and what they post is a claim about the agent, not a fact about the repository.

## Threats and mitigations

| #   | Threat                                                                 | Impact                                                 | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Residual risk                                                                                                                                                                                                                                                                                                                                                       |
| --- | ---------------------------------------------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | Interlock writes to a user worktree, index or branch and destroys work | unrecoverable data loss                                | typed `UserRepo`/`ShadowRepo` split; git runner refuses mutating argv against user repos; a data dir, shadow or worktree pool that resolves inside a watched repository is refused before anything is written; state-hash test                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | a git subcommand missing from the mutating list; keep the list under review                                                                                                                                                                                                                                                                                         |
| T2  | Merged agent code executes destructive behaviour on the host           | machine compromise                                     | Docker, driven through its CLI with argument arrays and never a host shell: no network; the daemon's own uid, and no run at all while the daemon is root; every capability dropped and `no-new-privileges`; the merged tree bind-mounted read-only on a read-only root filesystem, with writes only to a tmpfs that dies with the container; nested mounts only onto mount points already in the tree, never through a link; no host environment variable and no Docker socket; CPU, memory with no swap, process and wall-clock limits, each reported as the limit that fired and never as a result; an image pinned by digest and never pulled; every container labelled and removed on every path, and one a crashed daemon left behind found by its label; the type checker, which runs in the daemon rather than the sandbox, is Interlock's own pinned TypeScript, never the tree's `node_modules` copy, and strips `plugins` from every resolved tsconfig after its `extends` chain is read, so nothing from the repository is loaded | container escape; VM isolation would be stronger                                                                                                                                                                                                                                                                                                                    |
| T3  | Repository content or secrets exfiltrated during analysis              | data breach                                            | no network in the sandbox; no telemetry; credential files never read; the type checker reads only the files the merged tree lists, `node_modules` in the dependency checkout and its own `lib` files, in its own host, so a tsconfig's `include`, `files`, `paths` or `typeRoots` naming `~/.ssh`, a link in the tree pointing there, or a file left in the slot that the tree does not hold, reads nothing, and each of its workers starts with an empty environment; evidence stores spans and truncated excerpts                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | a build script that reads secrets and writes them into output that becomes evidence — hence redaction on stored evidence too                                                                                                                                                                                                                                        |
| T4  | Prompt injection through peer diffs delivered to an agent              | one agent steers another                               | `wrapUntrusted()`: delimiters, truncation, neutralised instruction-shaped lines — looked for at the start of a line and after every comment opener, read through full-width forms and invisible characters — with bidi controls and tag characters shown as escapes; minimal payloads; rate limits                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | a determined injection that reads as ordinary code                                                                                                                                                                                                                                                                                                                  |
| T5  | Another local process reaches the daemon API                           | information disclosure                                 | loopback-only bind; bearer token generated at first start, stored 0600                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | any process running as the same user can read the token file; that is the limit of a local-first design                                                                                                                                                                                                                                                             |
| T6  | Secrets leak into the store or logs                                    | credential exposure                                    | redaction patterns on all log records and evidence; 0700 data dir                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | pattern-based redaction misses novel formats                                                                                                                                                                                                                                                                                                                        |
| T7  | Disk exhaustion from shadow worktrees and caches                       | machine unusable                                       | one shadow clone per repository, borrowing the repository's objects through alternates rather than copying them; the database pruned to a retention window (`retention.windowMs`) once after start and then hourly, or every quarter of a shorter window, keeping only what an open or stale Finding, or a dismissal still holding its conflict back, rests on, with freed pages reused rather than the file growing; the shadow's own objects packed and collected in the same pass with `git repack --cruft -l` and `git prune` — never `gc`, and never the repository's objects — keeping what a live Finding's evidence names and each branch's last-seen content; `interlock daemon stop --purge` stops the daemon and deletes the whole data directory, refusing one that is not Interlock's or sits inside a watched repository, and removing links rather than following them                                                                                                                                                        | a collection that fails is retried on a backoff of up to a day, and the shadow grows until one succeeds; a single very large repository is still expensive; the user's `git gc` does not know the shadow borrows its objects, so one only the shadow still names — a branch deleted between refreshes — can be pruned under it until the next refresh drops the ref |
| T8  | Warning fatigue makes the tool counterproductive                       | real conflicts get ignored                             | precision-first matchers; ranking; rate limits; a dismissed conflict is not raised again while its content is unchanged; the rate of Findings dismissed as wrong is counted per rule and shown by `interlock status`, as bugs to fix and never as a threshold that suppresses output                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | subjective threshold; measure it rather than guessing                                                                                                                                                                                                                                                                                                               |
| T9  | Supply-chain compromise of a dependency                                | arbitrary code execution during builds                 | pinned lockfile, dependabot, `pnpm audit` in CI, minimal-dependency policy in `core`, the sandbox image pinned by digest rather than by tag                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | transitive dependencies of the dashboard toolchain remain broad                                                                                                                                                                                                                                                                                                     |
| T10 | A page in the user's browser reaches the daemon API                    | information disclosure                                 | bearer token required on every route, including paths that do not exist; the `Host` header must name a loopback address, so a domain resolving to 127.0.0.1 is refused; no CORS header is ever sent                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | a page that has obtained the token has the same access as any process running as the user                                                                                                                                                                                                                                                                           |
| T11 | A local process posts a forged agent session                           | misattribution                                         | the same bearer token as every route; every field validated and unknown keys refused; the working directory must lie inside a worktree the daemon already watches; a session is a claim the agent makes, never proof, and anything it chose is escaped before a terminal sees it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | a process holding the token can claim to be any agent on any watched branch; attribution informs advice and never gates a write                                                                                                                                                                                                                                     |
| T12 | A local process starts checks through the daemon API                   | resource use; repository content shown                 | the same bearer token as every route; a 4 KiB body, every field validated and unknown keys refused; branch names resolved against the store, never handed to git; a deadline of at most ten minutes, and a caller that hangs up stops the wait; a check queues one pair, the same work the scheduler does unasked; branch names, paths and excerpts are escaped before a terminal sees them, and each excerpt is first quoted with `wrapUntrusted()`, since agents run `check` as a gate and read what it prints                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | a process holding the token can keep the daemon busy with checks; branch names and paths are printed escaped but unwrapped, so a file named as an instruction reaches an agent running the CLI as one line of plain text (see below)                                                                                                                                |
| T13 | A local process dismisses Findings through the daemon API              | a real conflict hidden; the false-positive rate skewed | the same bearer token as every route; a 4 KiB body, every field validated and unknown keys refused; the reason an enum, the note at most 500 characters and escaped before a terminal sees it; the Finding id checked for shape before the store is asked; only an open or stale Finding can be dismissed, and a dismissal holds only while both sides of its file are unchanged; each dismissal is an event traced to the Finding's raise                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | a process holding the token can hide any open conflict until either side of its file changes, and can make the rate say anything; there is no undismiss short of an edit                                                                                                                                                                                            |

## What the CLI prints from a repository

An agent runs the CLI as readily as a person does, so everything it prints is read by a model. Every field below is escaped before a terminal sees it; this table is about the reader, not the terminal.

| Field                                      | Printed by                        | Treatment                      | Why                                                                                                                                                    |
| ------------------------------------------ | --------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Span excerpts                              | `check`                           | wrapped with `wrapUntrusted()` | another branch's code, comments included: multi-line free text, the shape an injection takes                                                           |
| Paths                                      | `check`, `status`, `dismiss`      | escaped, not wrapped           | one line each, and a delimiter block per path would bury the report; a file can still be named as an instruction, which is the residual risk T12 names |
| Branch names, the default branch           | `check`, `status`, error remedies | escaped, not wrapped           | one line each; git refuses spaces in a ref name, so an instruction can be spelt only as one hyphenated token                                           |
| The repository root                        | `status`                          | escaped, not wrapped           | a directory the user chose when configuring the daemon, not content the repository carries                                                             |
| Merge base and Finding ids                 | `check`, `dismiss`                | escaped, not wrapped           | hex from git and ULIDs from the daemon: no free text                                                                                                   |
| Finding titles, rules, severities, reasons | `check`, `status`, `dismiss`      | escaped, not wrapped           | written by the analyzers or enums; a title holds no repository content by design                                                                       |
| A dismissal's note                         | `dismiss`                         | escaped, not wrapped           | free text from whoever holds the token and dismissed the Finding (T13), not from the repository; at most 500 characters                                |

## Non-threats in v1

- Multi-user or team deployments. The moment a server component appears, this document needs a new section.
- Malicious users attacking their own machine.
- Windows-specific attack surface.

## Review checklist

- [ ] Does any new code path write to a user repository?
- [ ] Does any new code path execute repository code outside the sandbox?
- [ ] Does any new agent-facing payload go through `wrapUntrusted()`?
- [ ] Any new listener, and is it loopback + token?
- [ ] Any new stored field that could contain secrets or full file contents?
- [ ] Any new dependency in `core`, and does it have an ADR note?
