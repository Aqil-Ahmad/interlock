# Threat model

Reviewed as the sandbox and MCP server evolve.

## What Interlock is trusted with

| Asset                              | Why it matters                                            |
| ---------------------------------- | --------------------------------------------------------- |
| Uncommitted work in user worktrees | exists nowhere else; loss is unrecoverable                |
| Repository source code             | may be proprietary; must never leave the machine          |
| Developer machine and credentials  | the daemon runs with the user's privileges                |
| Agent attention                    | a warning channel that can be poisoned can steer an agent |

## Trust boundaries

1. **User repositories → Interlock.** Read-only.
2. **Merged code → execution.** Code produced by merging two agent branches has been reviewed by nobody. Untrusted input, executed only in the sandbox.
3. **Interlock → agents.** Everything forwarded is content other agents wrote. Untrusted data, wrapped as data.
4. **Localhost API.** Any process on the machine can reach a loopback port; the bearer token is the boundary. Agent hooks post through it, and what they post is a claim about the agent, not a fact about the repository.

## Threats and mitigations

| #   | Threat                                                                 | Impact                                                 | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Residual risk                                                                                                                                                                                                                                                                                                                                                       |
| --- | ---------------------------------------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | Interlock writes to a user worktree, index or branch and destroys work | unrecoverable data loss                                | typed `UserRepo`/`ShadowRepo` split; git runner refuses mutating argv against user repos; a data dir, shadow or worktree pool that resolves inside a watched repository is refused before anything is written; state-hash test                                                                                                                                                                                                                                                                                                                                                                                                                                        | a git subcommand missing from the mutating list; keep the list under review                                                                                                                                                                                                                                                                                         |
| T2  | Merged agent code executes destructive behaviour on the host           | machine compromise                                     | Docker: `--network=none`, non-root, read-only mount + tmpfs, cap-drop, pids/CPU/memory/time limits                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | container escape; VM isolation would be stronger                                                                                                                                                                                                                                                                                                                    |
| T3  | Repository content or secrets exfiltrated during analysis              | data breach                                            | no network in the sandbox; no telemetry; credential files never read; evidence stores spans and truncated excerpts                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | a build script that reads secrets and writes them into output that becomes evidence — hence redaction on stored evidence too                                                                                                                                                                                                                                        |
| T4  | Prompt injection through peer diffs delivered to an agent              | one agent steers another                               | `wrapUntrusted()`: delimiters, truncation, neutralised instruction-shaped lines; minimal payloads; rate limits                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | a determined injection that reads as ordinary code                                                                                                                                                                                                                                                                                                                  |
| T5  | Another local process reaches the daemon API                           | information disclosure                                 | loopback-only bind; bearer token generated at first start, stored 0600                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | any process running as the same user can read the token file; that is the limit of a local-first design                                                                                                                                                                                                                                                             |
| T6  | Secrets leak into the store or logs                                    | credential exposure                                    | redaction patterns on all log records and evidence; 0700 data dir                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | pattern-based redaction misses novel formats                                                                                                                                                                                                                                                                                                                        |
| T7  | Disk exhaustion from shadow worktrees and caches                       | machine unusable                                       | one shadow clone per repository, borrowing the repository's objects through alternates rather than copying them; the database pruned to a retention window (`retention.windowMs`) once after start and then hourly, or every quarter of a shorter window, keeping only what an open or stale Finding, or a dismissal still holding its conflict back, rests on, with freed pages reused rather than the file growing; the shadow's own objects packed and collected in the same pass with `git repack --cruft -l` and `git prune` — never `gc`, and never the repository's objects — keeping what a live Finding's evidence names and each branch's last-seen content | a collection that fails is retried on a backoff of up to a day, and the shadow grows until one succeeds; a single very large repository is still expensive; the user's `git gc` does not know the shadow borrows its objects, so one only the shadow still names — a branch deleted between refreshes — can be pruned under it until the next refresh drops the ref |
| T8  | Warning fatigue makes the tool counterproductive                       | real conflicts get ignored                             | precision-first matchers; ranking; rate limits; a dismissed conflict is not raised again while its content is unchanged; the rate of Findings dismissed as wrong is counted per rule and shown by `interlock status`, as bugs to fix and never as a threshold that suppresses output                                                                                                                                                                                                                                                                                                                                                                                  | subjective threshold; measure it rather than guessing                                                                                                                                                                                                                                                                                                               |
| T9  | Supply-chain compromise of a dependency                                | arbitrary code execution during builds                 | pinned lockfile, dependabot, `pnpm audit` in CI, minimal-dependency policy in `core`, pinned Docker base images                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | transitive dependencies of the dashboard toolchain remain broad                                                                                                                                                                                                                                                                                                     |
| T10 | A page in the user's browser reaches the daemon API                    | information disclosure                                 | bearer token required on every route, including paths that do not exist; the `Host` header must name a loopback address, so a domain resolving to 127.0.0.1 is refused; no CORS header is ever sent                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | a page that has obtained the token has the same access as any process running as the user                                                                                                                                                                                                                                                                           |
| T11 | A local process posts a forged agent session                           | misattribution                                         | the same bearer token as every route; every field validated and unknown keys refused; the working directory must lie inside a worktree the daemon already watches; a session is a claim the agent makes, never proof, and anything it chose is escaped before a terminal sees it                                                                                                                                                                                                                                                                                                                                                                                      | a process holding the token can claim to be any agent on any watched branch; attribution informs advice and never gates a write                                                                                                                                                                                                                                     |
| T12 | A local process starts checks through the daemon API                   | resource use; repository content shown                 | the same bearer token as every route; a 4 KiB body, every field validated and unknown keys refused; branch names resolved against the store, never handed to git; a deadline of at most ten minutes, and a caller that hangs up stops the wait; a check queues one pair, the same work the scheduler does unasked; branch names, paths and excerpts are escaped before a terminal sees them                                                                                                                                                                                                                                                                           | a process holding the token can keep the daemon busy with checks; `interlock check` prints repository excerpts to a terminal, which an agent running it reads without `wrapUntrusted()`                                                                                                                                                                             |
| T13 | A local process dismisses Findings through the daemon API              | a real conflict hidden; the false-positive rate skewed | the same bearer token as every route; a 4 KiB body, every field validated and unknown keys refused; the reason an enum, the note at most 500 characters and escaped before a terminal sees it; the Finding id checked for shape before the store is asked; only an open Finding can be dismissed, and a dismissal holds only while both sides of its file are unchanged; each dismissal is an event traced to the Finding's raise                                                                                                                                                                                                                                     | a process holding the token can hide any open conflict until either side of its file changes, and can make the rate say anything; there is no undismiss short of an edit                                                                                                                                                                                            |

## Non-threats in v1

- Multi-user or team deployments. The moment a server component appears, this document needs a new section.
- Malicious users attacking their own machine.
- Windows-specific attack surface.

## Review checklist

- [ ] Does any new code path write to a user repository?
- [ ] Does any new code path execute repository code outside the sandbox?
- [ ] Does any new agent-facing payload go through `wrapUntrusted()`?
- [ ] Any new listener, and is it loopback + token?
- [ ] Any new stored field that could contain secrets or full file contents?
- [ ] Any new dependency in `core`, and does it have an ADR note?
